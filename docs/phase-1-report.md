## Omnigent pin

- **Version:** 0.6.0.dev0 (editable install from local repo)
- **Commit:** 6e3c7785 (omnigent repo HEAD)
- **Recorded in:** `rickgent-policies/pyproject.toml` (dependency: `omnigent>=0.5.0`), decision log

## Deviations

- `rickgent-policies/pyproject.toml` uses `omnigent>=0.5.0` instead of a git URL pin. This is because the 0.6.0.dev0 version is not published to PyPI; the pin is enforced by the local editable install. For releases, the pyproject.toml will be updated to pin the exact version or commit.
- The `omnigent run <bundle> -p "ping"` one-shot verification (AC-1 last clause) requires a running omnigent server with an LLM provider configured. This is deferred to Phase 7 (end-to-end integration) where the full dispatch pipeline is exercised. The doctor check verifies the agent bundle parses and the CLI is available.
- Build_commit auto-detection for Python: for editable installs, the Python package auto-detects the build_commit from `rickgent --build-commit`. For release wheels, it will be set via `RICKGENT_BUILD_COMMIT` env var at build time.

## Items for human decision

1. **Omnigent pin strategy for releases:** The current editable install works for development. For releases, decide whether to pin to a published version (v0.5.0/v0.5.1) or publish 0.6.0.dev0 to an internal index.
2. **LLM provider configuration:** The `omnigent run` one-shot test requires an LLM provider API key. This needs to be configured before Phase 7.
