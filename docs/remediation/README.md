## Execution contract

1. Tickets execute in manifest order through the guaranteed sequential `codex exec` path.
2. Contract-decision tickets `t00` through `t02` must be resolved and reviewed before production implementation begins.
3. The first containment tranche is `t03` through `t07`.
4. No two implementation agents may edit the shared execution, state, policy, Git, or lifecycle contracts concurrently.
5. Parallel agents may perform read-only analysis and independent review.
6. A ticket is not complete merely because its implementation exists; its ticket-specific negative proofs and verification contract must pass.
7. Capability enablement remains separate from implementation and occurs only after the corresponding proof corpus passes.

## First-phase gate

- the Omnigent compatibility and identity-observation contract is explicit and executable;
- evidence provenance and clean-baseline handling are committed;
- execution, terminal-state, ticket, sandbox, commit-authority, and toolchain contracts are frozen;
- unsafe capabilities are structurally unavailable;
- zero, partial, gate, evidence, and cleanup failures return nonzero and cannot reach delivery;
- executable ticket contracts are normalized and hashed before dispatch;
- fixture mutation occurs only in a dedicated run worktree; and
- CLI help, doctor output, and documentation describe the actually available preview contract.

Implementation must stop at this gate for independent reliability review before advancing into native policy enforcement.
