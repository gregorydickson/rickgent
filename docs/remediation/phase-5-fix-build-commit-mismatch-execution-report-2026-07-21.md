## Scope

M5 scrutiny round 2 identified a blocking defect: the committed
`orchestrator/src/build-commit.ts` reports commit `028a06a` while the current
HEAD is `99f8e1c`. The fix worker's commit (`99f8e1c`) did not update
`build-commit.ts` to the new commit hash. This causes:

1. **TS/Python build-commit parity failure** — `test_build_commit_matches`
   (in `test_compat.py` and `test_ac19.py`) fails because the built CLI
   reports `028a06a` while `RICKGENT_BUILD_COMMIT` is pinned to `99f8e1c`.
2. **Policy corpus fail-closed** — `convergence_green` and
   `simplification_valid` events in
   `test_native_function_policy_corpus.py` get DENY instead of ALLOW because
   the convergence and simplification policies call `_verified_verdict`,
   which invokes `_assert_build_commit`; the build-commit mismatch raises a
   `RuntimeError`, causing the policies to fail closed to DENY.

## Root Cause

`pnpm build` regenerates `build-commit.ts` from `git rev-parse HEAD` before
compiling `dist/`. The fix worker for scrutiny round 1 committed `99f8e1c`
without first updating `build-commit.ts` to the new HEAD. The committed
`build-commit.ts` therefore still references the parent commit `028a06a`.
When a validator or worker builds `dist` from the stale committed
`build-commit.ts` (without the `generate-build-commit.cjs` regeneration
step), `dist/cli.js` reports `028a06a`, mismatching the env-pinned
`RICKGENT_BUILD_COMMIT=99f8e1c`.

`init.sh` step 6a restores `build-commit.ts` to its committed value after
rebuilding `dist`, so the stale committed value is the source of the
mismatch: `init.sh` rebuilds `dist` to current HEAD (correct), but the
committed `build-commit.ts` remains stale, violating git-tree-truth.

## Fix

Update `orchestrator/src/build-commit.ts` to report the current HEAD commit
hash (`99f8e1cca4783f69ba953a9482c9357019adfa49`). Rebuild `dist` via
`pnpm build` to confirm the build is green and `dist/cli.js` reports the
same commit.

**Files changed:**
- `orchestrator/src/build-commit.ts` — `BUILD_COMMIT` updated from
  `028a06afd07b3b7eefe145219c4e817c89d03dca` to
  `99f8e1cca4783f69ba953a9482c9357019adfa49`.

`dist/cli.js` and `dist/build-commit.js` are gitignored (`dist/` in
`.gitignore`) and are regenerated by `init.sh` / `pnpm build`; they are not
committed.

## Known limitations

- `dist/cli.js` is gitignored and not committed; it is regenerated by
  `init.sh` / `pnpm build`. The fix ensures the committed
  `build-commit.ts` source matches HEAD so that any build from the committed
  source produces a `dist` that reports the correct commit.
- The build-commit hash will lag by one commit after this fix commit (the
  established chicken-and-egg pattern: `build-commit.ts` references the
  commit it was built against, not the commit that commits it). `init.sh`
  handles this by rebuilding `dist` to current HEAD on every session and
  pinning `RICKGENT_BUILD_COMMIT` to the rebuilt value.
